# Contract examples

Status: informative

These fixtures illustrate the versioned API envelope and representative clinical branches. They are suitable for documentation, client-generation smoke tests, and contract tests. They are not a substitute for the independently derived clinical validation suite required by [the test and validation specification](../09-test-and-validation.md).

Fixture UUIDs, timestamps and digests are synthetic. The paired response is deliberately marked `demonstration` with a `draft` rule pack; no fixture asserts clinical authorisation.

| Scenario | Request | Response or problem |
|---|---|---|
| Below treatment threshold | [`normal-below-threshold-request.json`](normal-below-threshold-request.json) | [`normal-below-threshold-response.json`](normal-below-threshold-response.json) |
| Jaundice in the first 24 hours | [`early-jaundice-request.json`](early-jaundice-request.json) | To be generated by the implementation contract suite |
| Phototherapy indicated | [`phototherapy-request.json`](phototherapy-request.json) | To be generated by the implementation contract suite |
| Intensified phototherapy indicated | [`intensified-phototherapy-request.json`](intensified-phototherapy-request.json) | To be generated by the implementation contract suite |
| Exchange escalation | [`exchange-escalation-request.json`](exchange-escalation-request.json) | To be generated by the implementation contract suite |
| Prolonged jaundice | [`prolonged-jaundice-request.json`](prolonged-jaundice-request.json) | To be generated by the implementation contract suite |
| Stale rule-pack precondition | Not applicable | [`stale-rule-pack-problem.json`](stale-rule-pack-problem.json) |
| Invalid request | Not applicable | [`validation-problem.json`](validation-problem.json) |

Before release, every request fixture must have a paired golden response produced from an independent clinical oracle, and every response must validate against [`../openapi.yaml`](../openapi.yaml).

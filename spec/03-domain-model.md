# Domain model

## Design principles

The domain model prevents common clinical-software errors at the type and validation boundary:

- age is elapsed minutes, not an ambiguous date or rounded hour;
- gestation is completed weeks, not a decimal or corrected gestation;
- bilirubin uses one explicit UK unit;
- unknown is distinct from absent;
- serum and transcutaneous values cannot be confused;
- rule-pack identity is part of every evaluation; and
- identifiers and free text are not accepted.

## Scalar types

| Type | Wire representation | Valid values |
|---|---|---|
| `RulePackId` | string | Pattern `^[a-z0-9][a-z0-9.-]{0,63}$` |
| `EvaluationId` | UUID string | UUID v7 generated by the API |
| `RequestId` | string | 1–64 printable ASCII characters, generated when absent |
| `GestationalWeeks` | integer | 23–42 |
| `AgeMinutes` | integer | 0–40,319; treatment-state ages may not exceed assessment age |
| `BilirubinUmolL` | integer | 0–1,000 |
| `TriState` | string enum | `present`, `absent`, `unknown` |
| `MeasurementMethod` | string enum | `serum`, `transcutaneous` |
| `TreatmentMode` | string enum | `none`, `phototherapy`, `intensified_phototherapy`, `post_phototherapy`, `post_exchange` |
| `Priority` | string enum | `emergency`, `immediate`, `urgent`, `treatment`, `timed`, `routine` |
| `ThresholdRelation` | string enum | `below`, `at`, `above`, `not_available` |

## EvaluationRequest

```text
EvaluationRequest
├── rule_pack_id: RulePackId
├── gestational_age_completed_weeks: GestationalWeeks
├── assessment_age_minutes: AgeMinutes
├── clinical_features: ClinicalFeatures
├── risk_factors: RiskFactors
├── measurements: Measurement[0..64]
├── conjugated_bilirubin_umol_l?: BilirubinUmolL
└── treatment_state: TreatmentState
```

| ID | Requirement |
|---|---|
| DATA-001 | All request objects MUST reject properties not declared by the schema. |
| DATA-002 | `rule_pack_id`, gestation, assessment age, clinical features, risk factors, measurements and treatment state MUST be present. |
| DATA-003 | An assessment MAY contain no measurement when the requested support is recognition, measurement method or prolonged-jaundice assessment. |
| DATA-004 | An assessment requiring numeric threshold interpretation MUST contain at least one valid measurement. |
| DATA-005 | A request MUST contain no more than 64 measurements and MUST be no larger than 64 KiB. |
| DATA-006 | A request MUST NOT contain a name, identifier, absolute timestamp, postcode, address, contact detail or free-text field. |

## ClinicalFeatures

Every field is required and uses `TriState` unless stated otherwise.

| Field | Meaning |
|---|---|
| `suspected_or_obvious_jaundice` | Jaundice is suspected or obvious at assessment |
| `visible_jaundice` | Visual jaundice is present |
| `clinically_well` | The clinician has assessed the baby as clinically well |
| `acute_bilirubin_encephalopathy` | Clinical features/signs are present |
| `pale_chalky_stools` | Pale/chalky stools are reported or observed |
| `dark_urine_stains_nappy` | Dark urine staining the nappy is reported or observed |
| `rhesus_haemolytic_disease` | Rhesus haemolytic disease is established |
| `abo_haemolytic_disease` | ABO haemolytic disease is established |
| `infection_suspected` | Infection is clinically suspected |
| `urinary_tract_infection_suspected` | UTI is clinically suspected |
| `routine_metabolic_screen_completed` | Routine newborn metabolic screening is confirmed |

An `unknown` danger sign contributes to `missing_information` and blocks a reassuring primary action. It does not activate the corresponding positive rule.

## RiskFactors

| Field | Meaning |
|---|---|
| `previous_sibling_required_phototherapy` | Previous sibling had neonatal jaundice requiring phototherapy |
| `exclusive_breastfeeding_intended` | Mother intends to breastfeed exclusively |

Gestation under 38 weeks and visible jaundice in the first 24 hours are derived rather than supplied as duplicate risk fields.

## Measurement

```text
Measurement
├── id: string (1..32, request-local)
├── age_minutes: AgeMinutes
├── total_bilirubin_umol_l: BilirubinUmolL
└── method: MeasurementMethod
```

| ID | Requirement |
|---|---|
| DATA-007 | Measurement IDs MUST be unique within a request and have no meaning outside it. |
| DATA-008 | Measurement ages MUST be unique and no later than `assessment_age_minutes`. |
| DATA-009 | The server MUST sort measurements by age after validation; array order MUST NOT change clinical meaning. |
| DATA-010 | A later measurement age with an earlier collection sequence cannot be represented; clients MUST submit the actual elapsed collection age. |
| DATA-011 | Duplicate ages MUST be rejected rather than averaged or resolved automatically. |
| DATA-012 | Bilirubin values MUST NOT be converted, rounded or clamped by the server. |

## TreatmentState

```text
TreatmentState
├── mode: TreatmentMode
├── started_age_minutes?: AgeMinutes
├── stopped_age_minutes?: AgeMinutes
└── exchange_completed_age_minutes?: AgeMinutes
```

Invariants:

- `none`: all optional ages absent.
- `phototherapy` or `intensified_phototherapy`: `started_age_minutes` required; other ages absent.
- `post_phototherapy`: start and stop required; stop must be later than start.
- `post_exchange`: `exchange_completed_age_minutes` required; phototherapy start may be present.
- every treatment age must be no later than assessment age.

| ID | Requirement |
|---|---|
| DATA-013 | Invalid treatment-state combinations MUST return field-specific validation errors. |
| DATA-014 | The engine MUST NOT assume a missing treatment time from measurement times. |

## Derived evaluation types

### ExactThreshold

Internal only:

```text
ExactThreshold
├── numerator: signed 64-bit integer
└── denominator: positive 64-bit integer
```

Fractions are reduced before storage in the decision trace. Cross multiplication MUST use checked arithmetic; overflow returns an internal safety failure and no clinical result.

### ThresholdAssessment

| Field | Type | Meaning |
|---|---|---|
| `measurement_id` | string | Measurement evaluated |
| `age_minutes` | integer | Measurement age |
| `phototherapy_threshold_umol_l` | number/null | One-decimal display value |
| `phototherapy_relation` | enum | Exact relationship |
| `phototherapy_distance_umol_l` | number/null | Signed measurement minus threshold |
| `exchange_threshold_umol_l` | number/null | One-decimal display value |
| `exchange_relation` | enum | Exact relationship |
| `exchange_distance_umol_l` | number/null | Signed measurement minus threshold |
| `treatment_decision_eligible` | boolean | True only for serum |

### TrendAssessment

| Field | Type | Meaning |
|---|---|---|
| `older_measurement_id` | string |
| `newer_measurement_id` | string |
| `interval_minutes` | integer |
| `rate_umol_l_per_hour` | number | One-decimal display only |
| `direction` | `rising`, `stable`, `falling` |
| `reliable_for_rapid_rise` | boolean | Both values are serum and their validated ages are distinct |
| `rapid_rise_relation` | `below`, `at`, `above`, `not_available` | Exact relationship to 8.5 |

## Recommendation

```text
Recommendation
├── code: SCREAMING_SNAKE_CASE string
├── priority: Priority
├── category: string enum
├── action: string
├── timeframe?: Timeframe
├── rationale: string
├── source_refs: SourceReference[1..n]
├── requires_serum_confirmation: boolean
└── requires_clinician_confirmation: true
```

Allowed categories are `emergency`, `measurement`, `monitoring`, `phototherapy`, `exchange_transfusion`, `underlying_disease`, `prolonged_jaundice`, `feeding_support`, and `information`.

`Timeframe` contains a unit and either an exact value or inclusive minimum/maximum. Timeframes are never converted into appointment timestamps by the server.

| ID | Requirement |
|---|---|
| DATA-015 | Recommendation codes MUST be stable within API v1 and MUST NOT be reused for different meanings. |
| DATA-016 | Human-readable action text MUST use UK English and MUST NOT weaken its mapped NICE recommendation. |
| DATA-017 | Every recommendation MUST require clinician confirmation. |
| DATA-018 | Source references MUST contain the NICE product ID, recommendation number and canonical URL. |

## EvaluationResponse

```text
EvaluationResponse
├── evaluation_id: EvaluationId
├── request_id: RequestId
├── evaluated_at: RFC 3339 timestamp
├── mode: demonstration | clinical
├── api_version: string
├── engine_version: string
├── rule_pack: RulePackSummary
├── normalised_input: NormalisedInputSummary
├── thresholds: ThresholdAssessment[]
├── trend?: TrendAssessment
├── primary_action: Recommendation
├── recommendations: Recommendation[]
├── warnings: Warning[]
├── missing_information: MissingInformation[]
├── suppressed_rules: string[]
├── decision_receipt: DecisionReceipt
└── legal: LegalNotices
```

The `normalised_input` and decision receipt contain only fields already permitted in the request. The receipt is not cryptographically signed in v1; it includes a SHA-256 digest of the canonical normalised input and decision payload so accidental changes can be detected by clients. The server does not retain either the receipt or digest.

| ID | Requirement |
|---|---|
| DATA-019 | Successful responses MUST include one `primary_action`, including when that action is to complete missing information or follow local protocol. |
| DATA-020 | `recommendations` MUST include the primary action exactly once as its first item. |
| DATA-021 | Warnings MUST use stable codes and MUST distinguish clinical, scope, source, assay and system warnings. |
| DATA-022 | The response MUST identify rules suppressed by conflict resolution without exposing executable internals. |
| DATA-023 | `evaluated_at` is operational metadata and MUST NOT be used to infer postnatal age. |

## Validation errors

Validation follows two layers:

1. schema validation: types, required fields, ranges and unknown properties;
2. domain validation: chronological order, treatment-state invariants and clinical preconditions.

All discovered field errors are returned together when safe. No threshold or recommendation is returned alongside an invalid request. Error field paths use RFC 6901 JSON Pointers.
